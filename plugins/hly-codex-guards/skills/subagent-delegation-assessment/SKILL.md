# Subagent Delegation Assessment

仅在用户明确调用后评估适用性；评估不是委派或原任务执行授权。Task Decomposition、Context Isolation 与 Subagent Delegation 是独立概念；Task Decomposition 不自动触发 Subagent。实际调用由 Codex Native Harness 决定，本 Skill 不规定 Agent Loop、数量、顺序或等待方式。

## 评估与结论

多服务/仓库/模块、独立工作流、多风险维度 Review、日志/测试输出/搜索结果可作为候选，不能仅按数量或文件边界拆分。根据任务输入、返回证据、共享语义、写入冲突及新增交接/复核工作选择；额度比较只引用已有可比任务的用量记录，缺少记录时注明未知，不为本评估额外试跑：

- **现在委派**：能列明任务目标、输入、返回证据与完成条件，无需持续等待主任务的中间决定；指出可并行的工作或可独立汇总返回的调查，以及新增交接/复核工作。可写任务还须满足下一节全部条件；不把并行或摘要返回当成节省额度的证据。
- **后续阶段委派**：公共协议或业务口径未定；只读调查/测试可作候选，共享语义明确后再评估可写实现，不按不同假设并行修改。
- **保持单 Agent**：单点/单风险/单 SQL 条件/字段/注释修改、单一不可拆调用链、工作集中在一处、持续共享中间状态、写入范围无法隔离，或交接与复核需要重复执行原任务的同一调查/实现。用户明确优先节约额度且没有可比用量依据时，也保持单 Agent。

默认只给结论、候选任务及具体原因，不输出完整评估表；用户询问策略依据时再展开。

## 共享语义与写入

可独立调查服务调用链、producer/consumer 契约、DB/SQL、MQ、配置、外部接口、日志或测试失败及只读 Review。

公共 API/DTO/枚举/消息/表结构/Liquibase/SQL，权限、金额/支付结算、状态机、幂等补偿、迁移、发布顺序及共享配置，由主 Agent 或唯一负责人统一；子 Agent 提供证据，不各自决定口径。

仅当以下条件全部成立时才考虑可写实现：接口与业务语义已有确认依据；任务写入边界已列明、修改范围不重叠，且不修改同一公共协议；各任务有验收条件和可用验证方式，依赖满足后可单独验收；所有子 Agent 使用同一份确认事实；主 Agent 能读取并检查全部最终 diff。任一条件未确认时不推荐可写委派，只评估授权内的只读调查、测试或 Review。

## 权限继承与验收

子 Agent 继承原任务的只读、Review 不得修复、当前 diff/单风险/服务/目录/文件范围及测试和操作授权，不因委派获得额外权限。

委派说明包含目标、允许调查范围、禁止修改、返回证据、不得自行决定的共享语义；可写任务另含允许修改范围、必须保持的业务语义、验证要求和阻塞条件。无需固定空模板。

实际执行原任务时，无论是否委派，均需去重结论、处理冲突、复查关键证据、检查完整 diff 并报告未验证项与风险。本次变更影响跨服务或跨模块交互时，核对共享语义与接口/数据衔接并执行对应联合验证；不涉及这些交互时，不由本条追加联合验证，测试和操作仍受原授权限制。子任务完成不等于整体完成；仅评估时不执行这些业务动作。

不修改 Codex 配置、不新增 Agent 运行配置、不指定模型/推理档位/数量/并发；工具、模型和降级策略由宿主处理。
