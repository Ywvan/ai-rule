# Subagent Delegation Assessment

## 使用声明

- 执行本 Skill 的任何实质性操作前，必须先在用户可见消息中明确声明：`正在使用 $<Skill 名称>：<使用原因>`。
- 同时使用多个 Skill 时，必须一次列出全部 Skill 及使用顺序。
- 不得只在最终答复中事后补充声明；如果当前环境没有独立的进度消息通道，应在首条可见回复中声明。

## 目标

评估当前原始任务是否值得使用 Subagent，并在净收益明确且环境支持时进行有界委派。

本 Skill 是当前原始任务的横向前置评估。完成评估或必要的 Subagent 委派后，必须继续执行用户原始任务；不得只输出 Agent 使用建议后停止。

仅当用户明确只要求 Agent 策略、原任务存在必须停止的业务阻塞项，或当前环境不允许继续执行原任务时，才可以停止在评估结论。

本 Skill 兼容用户当前选择的模型、推理档位以及单 Agent、Ultra 和子 Agent 执行方式。

## 触发条件

出现下列任一情况时，先简短评估 Subagent：

- 涉及两个或以上服务、仓库或可独立调查的模块；
- 存在两个以上可独立实现、验证或 Review 的工作流；
- 需要读取大量日志、测试输出或文件搜索结果，辅助调查会明显污染主 Agent 上下文；
- 当前 Review 涉及多个相互独立的服务或风险维度。

触发评估不代表必须委派。多服务或多仓库本身不是充分理由。

## 不适用场景

以下情况默认保持单 Agent，且无需输出完整评估：

- 单文件局部修改、单风险修复、单个 SQL 条件或单个字段、注释修改；
- 单一调用链且无法有效拆分，或大部分工作集中在同一服务；
- 工作量很小、子任务需要持续共享中间状态，或用户明确优先节约额度且独立收益不明显。

不要按文件、类、服务或仓库机械拆分任务。

## 评估结论

必须明确选择一种结论：

### 现在委派

当独立工作流边界清晰、可以独立完成并压缩返回证据，且预期收益高于协调成本和额度成本时，使用完成任务所需的最少数量进行委派。当前环境支持 Subagent 时必须实际启动有界委派，等待当前任务所必需的结果，汇总后继续原始任务。

### 后续阶段委派

当可以独立调查，但公共协议、共享业务语义或状态口径尚未稳定时，当前可以并行调查或测试；由主 Agent 或唯一负责人先确认共享语义，之后重新评估可写实现。不得让不同 Agent 按不同业务假设并行修改。

### 保持单 Agent

当任务小、高度耦合、修改范围不能隔离、主要工作集中在一个服务，或协调成本、额度成本高于预期收益时保持单 Agent。只给出一至三条具体原因，并继续原始任务。

## 调查任务

优先考虑委派可独立返回证据的只读调查：不同服务或仓库的调用链、接口提供方与消费方核对、数据库、SQL、MQ、配置或外部接口分别调查、大量日志或测试失败分类、范围独立的只读 Review。

公共 API、DTO、枚举、消息协议、表结构、Liquibase、公共 SQL、权限、金额、支付结算、状态机、幂等补偿、历史迁移、发布顺序和多服务共享配置由主 Agent 或唯一负责人收口。Subagent 可以提供证据，不分别形成冲突的最终口径。

## 可写实现

仅在共享接口和业务语义已明确、服务或模块边界清晰、修改范围不重叠、不修改同一公共协议、可以独立验证、所有 Subagent 继承相同确认事实，且主 Agent 能检查全部最终 diff 时，评估可写实现。

不满足时，只允许并行调查、测试或只读 Review；可写实现由主 Agent 或唯一负责人顺序完成。

## 权限继承

- 原任务只读、技术方案或 Review 时，所有 Subagent 必须只读；Review 不得修复。
- 当前 diff、单风险、服务、目录、文件或当前轮范围限制必须完整继承，不得扩大到历史问题、其他风险或后续轮次。
- Subagent 不能因被单独委派而获得更大的权限。

调查或只读任务必须说明：

```text
任务目标：
允许调查范围：
禁止修改：
需要返回的证据：
不得自行决定的共享语义：
```

可写任务还必须说明：

```text
允许修改范围：
必须保持的业务语义：
验证要求：
阻塞条件：
```

## 主 Agent 责任

主 Agent 负责汇总和去重结论、处理冲突、复查关键证据、确认共享业务语义与跨服务接口一致性、检查完整最终 diff、执行联合验证，并输出未验证项和剩余风险。Subagent 分别完成不等于整体任务完成。

## 模型与配置边界

不修改 Codex 配置，不要求新增 Agent 配置文件，不指定具体模型或推理档位，不预设具体 Subagent 数量或并发数量，也不要求切换 Ultra。当前未使用 Ultra 不能直接作为跳过评估的理由；当前环境不支持 Subagent 时回退单 Agent并继续任务。

## 输出要求

默认简短输出结论，不让评估内容压过业务结果：

```text
Subagent：现在委派。
任务：分别调查 order-service 和 user-service 的调用链。
共享接口语义由主 Agent 统一确认。
```

```text
Subagent：后续阶段委派。
当前先并行调查两个服务；公共协议确认后重新评估并行实现。
```

```text
Subagent：保持单 Agent。
原因：第二个服务仅核对一个已有字段，委派收益不足。
```

只有用户明确询问 Agent 策略时，才输出完整评估依据。
